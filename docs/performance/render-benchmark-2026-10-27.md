# 渲染性能实测：2026-10-27

在本机 Apple M4 上测完 13 个主题、54 类业务页面和 17 类公共组件，以及 5 个主题的专有组件组合。共 1154 个组合，执行 8,078 次绘制与 PNG 编码，零失败。

## 测量口径

Python 3.12.11，Pillow 11.3.0，macOS 26.5.1。单进程顺序执行，每个组合先执行一次、再预热一次，然后测量 5 次。表内每个场景先取 5 次中位数；主题总览再对 54 个场景等权取中位数。各列分别取中位数，因此绘制与编码两列相加未必等于总耗时列。

组件对比 1× 与 2× 采样；业务页面使用当前默认设置（共享渲染管线为 2×）。包含页面构建、测量布局、绘制、缩图及 PNG 编码；不含导入启动、数据库取数、头像下载、线程池排队和消息发送。使用固定样例与已预热的字体/资源缓存，首轮数据单独保存在 JSON 中，不代表进程或操作系统冷启动。

业务样例复用预览与测试的数据构建器，计时内调用的数据构建器也计入；21 点牌面是预览用程序生成图，其生成耗时也计入。各主题可能采用不同尺寸及专用排版，因此表格反映这批场景的成本，不能直接当作生产流量的平均响应时间。5 次采样只报告实测范围，不据此估算生产 P95。

## 首轮调用与缓存影响

固定输入的预热数据更接近重复发送同一类页面的成本。首轮样本中，Mewtype 巡演帮助页为 **2075 ms**，预热后为 **364 ms**；魔女审判巡演帮助页为 **1417 ms → 364 ms**；Roselia 为 **945 ms → 326 ms**。这些是本次顺序测试中该场景的第一次调用，前面已经运行过其他场景，不能当作完整冷启动结果。

代码有字体缓存、按文字/字体/宽度缓存的换行结果，以及资源图片缓存。不断变化的长文字未必能获得固定样例的缓存收益；上面的主题排名应与首轮数据一起看。本次没有测多请求并发和线程池排队。

## 慢项定位与优化顺序

单独使用 cProfile 对三个已预热场景各执行 3 次绘制和编码，结果未混入基准统计：

- 霓虹巡演帮助页：绘制累计约 1006 ms，高斯模糊约 500 ms，占绘制时间约 50%。可优先验证按尺寸及视觉参数缓存阴影/发光层。
- Fluent 巡演帮助页：高斯模糊、图片缩放、透明合成和 PNG 编码都有明显成本，单改文字布局预计无法解决主要开销。
- 魔女审判帮助总览：PNG 编码累计约 528 ms，总耗时约 990 ms，占约 53%；图片缩放约 263 ms。`book_paper()` 每次切分并缩放两页书纸，可优先验证按尺寸与书脊位置缓存结果，再评估 PNG 压缩参数的速度/体积取舍。

上述是待验证的优化方向，本次只新增测速入口和报告，没有改变生产渲染、默认倍率或编码参数。

渲染相关回归检查通过：90 个测试、149 个子测试；两个脚本的 Ruff 检查及 `git diff --check` 通过。

## 复现与原始数据

```bash
.venv/bin/python scripts/benchmark_render.py --repeats 5 \
  --output-dir .cache/render-benchmark-2026-10-27
```

缩小范围可使用 `--kits kasumi roselia`、`--groups component`、`--ratios 1 2` 和 `--case pull-ten`。脚本只运行测试环境初始化，不启动机器人连接。

详细矩阵、每次样本、图片尺寸和 PNG 大小：

- `.cache/render-benchmark-2026-10-27/report.md`
- `.cache/render-benchmark-2026-10-27/results.json`
- `.cache/render-benchmark-2026-10-27/results.csv`
- `.cache/render-benchmark-2026-10-27/theme-speed.png`

另保存 3 组 `profile-*.txt` / `.prof`，用于定位绘制和编码中的 CPU 开销。分析器有额外开销，其时间不混入上面的基准。巡演排行榜在主测试后按相同参数补测，记录在 JSON 的 `supplemental_runs` 中。
