# 冬日群像主题设计

状态：已实现并注册 `winter_ensemble`，实际业务预览和验收入口见赛季规划 §10。

日期：2026-11-17。

建议注册名：`winter_ensemble`；建议实现类：`WinterEnsembleKit`。

赛季阵容、卡池、奖励与排期见[第五赛季规划](winter-ensemble-season-plan.md)。

## 1. 设计结论

采用已预览的签到、排行榜小样方向：雪蓝背景、暖白纸面、深蓝文字、红色印记，
以纸张的组织方式、留白、对齐和数字层级构成主题识别。

主题面向冬日邦邦群像。普通业务页面以内容为主体；人物主要出现在资料、立绘、
卡池和抽卡结果等本来需要人物的场景。签到和排行榜不依赖人物插画成立。

**用 layout 表达气氛，不用反复写出的主题名称、口号或装饰小字解释设计。**

本文件记录最终设计方向。此前印象图中的群像海报构图，以及此前提出的阶段性
主题变化，不作为实现依据。界面小样是比例与质感参考，其中的示例数据和小字号
不直接用作生产参数。

## 2. 文案与信息边界

每段文字必须至少承担一种作用：标识当前功能、呈现真实数据、说明状态、帮助操作。
删除文字后不影响这些作用的装饰性文案，默认删除。

| 小样中的内容 | 最终处理 |
| --- | --- |
| 页眉、页脚反复出现的「冬日合奏」「把冬夜唱亮」 | 删除；主题名称仅在主题列表、装备信息等需要辨认物品的位置出现 |
| `KASUMI / WINTER ENSEMBLE`、`SEASON 05` | 不作为通用页眉；赛季编号只在需要它的赛季页面出现 |
| `TODAY’S REWARD`、`YOUR RANK` 等英文翻译 | 删除；保留中文业务标签，不用双语小字填补留白 |
| 装饰日期、虚构印章编号、纪念年份 | 删除；仅在签到日期、邮件时间、赛季起止等真实业务需要时显示 |
| 「每一次到来，都值得被记住」等气氛句 | 删除；由间距、纸面和印记表达温度 |
| 「今日签到」「赛季排行」 | 保留，一个页面一个清楚的主标题 |
| 连签天数、余额、任务进度、距上一名的积分差 | 按真实数据保留，建立主次层级 |
| `/每日任务` 等操作提示 | 仅在有帮助时保留一处，不制作每页相同的宣传页脚 |

允许留白，不为填满空隙增加标签、装饰文字或指标。
不把余额、排行榜、任务等业务名称改成需要用户猜测含义的诗意名称。

## 3. 参考主题与视觉语言

### 3.1 从现有主题继承的设计方法

参考 [MewtypeKit](../../plugins/render/kits/mewtype/kit.py) 的清楚层级、明亮正文面、
醒目数字，以及标题与容器一致的视觉语言。

参考 [魔女审判主题](../../plugins/render/kits/manosaba/README.md) 的材质控制和
按业务单独设计的页面布局：资料、签到、列表和结果页各自组织信息，共享字体、
间距、纸面、线条与装饰规则。

冬日主题使用自己的纸面、轮廓和配色。标题不沿用 mewtype 的大渐变描边，
正文不使用魔女审判的旧书折痕、藤蔓与墨迹字牌。

### 3.2 配色与职责

| Token | 色值 | 职责 |
| --- | --- | --- |
| `snow` | `#E5EDF2` | 页面外部空间，形成冷色环境 |
| `paper` | `#FFF8EC` | 正文纸面、票券与资料底板 |
| `ink` | `#243B53` | 正文、标题、核心数字、深色身份区 |
| `muted` | `#5C6F7E` | 次要标签和辅助说明；不用于必读正文 |
| `line` | `#CDD2CF` | 低权重分隔线，不承载文字信息 |
| `stamp` | `#A84B50` | 签到印记、本人索引、重要状态标识 |
| `amber` | `#D58A45` | 小范围灯光、礼物与特殊结果装饰 |
| `pine` | `#47665B` | 少量可选植物装饰，不作为额外状态色 |

浅色区域占画面主体。暖白纸面与雪蓝外部形成稳定的冷暖关系，深蓝负责阅读，
红色集中标记，琥珀色点到为止。普通页面不必使用全部颜色。

核心文字使用 `ink`，避免橙色小字和浅色细字。
深色实心强调块采用深蓝底、暖白字；红色、琥珀色优先用于描边、印记和局部点缀。
实现时检查实际背景上的对比度，不以色板中的单个色值代替验证。

### 3.3 材质与轮廓

- 雪蓝背景使用极轻的明暗差和稀疏雪点，正文下方保持干净。
- 暖白纸面保持平整，以细边和短投影交代厚度；纹理只在大面积空白中隐约可见。
- 大多数页面使用一张主要纸面，通过留白、对齐与细线分组；不为每个字段再套一张卡片。
- 虚线表示可撕票根或一段记录的边界；实线负责表格和普通分区，二者有各自用途。
- 短胶带、票券缺口、盖章每页选用少量。不得每个容器都同时贴胶带、打孔、盖章。
- 建筑剪影仅作为页边的低矮收边，可省略；不做大幅背景风景，不压正文。
- 灯光仅在边缘、物品展示或高稀有度结果中出现。普通列表不需要灯串来证明主题。

## 4. 排版系统

### 4.1 画面结构

常规页面以约 896px 逻辑宽度起步，内容决定高度。外边距通常 50–56px，
纸面内边距 32–50px，分区间距 24–32px，小间距 8–18px。
最终宽度随业务内容测量，不强行把所有页面装进同样的固定高度。

页面顶部仅保留功能标题及必要状态。标题与正文之间用间距建立层级；
没有真实日期或编号时，不补一个假的右侧信息块来凑对称。

每页先确定一个阅读起点：签到的入账数、排行榜的本人名次、邮件的标题与正文、
抽卡结果的人物或物品。其余内容围绕这一重点安排。

### 4.2 字体与数字

- 标题采用有适度圆润感的粗体中文字体；正文采用清晰的中文黑体。
- 主标题约 40–56px；正文约 24–30px；必要标签不低于 22px。
- 奖励和本人名次可使用 64–80px 展示数字；普通列表数字保持紧凑。
- 数字字体可有少量印刷品气质，列表优先等宽数字并右对齐，避免积分列跳动。
- 同一页面最多两套字体体系；英文字体只用于真实拉丁文本或数字，不补英文副标题。
- 字体从仓库中可用、许可明确、中文覆盖充分的字体里选择，并在预览阶段确认。

网页小样中的 9–15px 辅助字属于缩略展示，生产 PNG 必须按仓库可读性规则重新定标。

### 4.3 信息分组与装饰

优先通过对齐、宽度、字号和空间分组，分隔线只在阅读需要时使用。
圆角保持克制，避免将所有内容都放进药丸或圆角指标卡。

印章表达真实状态，例如签到成功、奖励已领取；不能只是无意义地写一个主题名。
状态还须有文字或形状区别，不能仅靠红绿颜色区分。

## 5. 关键页面布局

### 5.1 签到

```text
今日签到                       实际日期（如业务提供）

┌─────────────────────────────────────────┐
│ 头像  昵称 / 等级                签到成功 │
│                                         │
│ 今日入账                   连续签到      │
│ +120 Pt                    07 天         │
│ 赛季余额 1,234 Pt                        │
│                                         │
│ 本轮签到印记                       5 / 7 │
│   已签   已签   已签   已签   已签   6   礼 │
│ 再签到 2 天，可获得 60 星星贴纸            │
│                                         │
│ 今日任务                         进行中  │
│ 完成一次猜谱面                           │
│ 完成后可领取 20 星星贴纸                  │
└─────────────────────────────────────────┘
必要时显示操作提示
```

示意数据不代表奖励配置。今日入账为第一重点，连续签到为第二重点。
余额保持普通文本，不与奖励争夺视觉权重。

连签以一排真实进度印记体现，完成印记略有角度差异，但位置、角度必须确定。
奖励节点与已签到状态分别编码，任务奖励须与已经到账的奖励明确分区。
没有任务、升级或连签额外奖励时，移除对应区域并收紧高度。

### 5.2 排行榜

顶部用一块横向留白区域呈现本人名次，右侧放本人积分与距上一名的差值，
下方直接接排行榜表格。本人没有上榜时显示真实状态，不虚构名次。

排名、玩家、积分使用稳定列宽。玩家列保留头像、头像框及昵称，积分右对齐。
本人行用细红索引边和轻微底色定位，并明确标记本人。
前三名以名次字重、徽记或局部线条区别，不额外堆三张巨大的获奖海报。

长榜通过实际行高与列距维持密度，取消重复的逐行卡片边框。
内容结束后自然收边，不添加主题口号。

### 5.3 个人资料

身份、称号、简介和资产构成主要阅读区。人物存在时以独立列展示，
使用完整比例并保留呼吸空间，不把人物铺到文字后面。

没有立绘时，信息区独立成立；不为填空自动放入一张固定人物大图。
头像缺失使用昵称首字。未装备称号、头像框和空简介按现有槽位契约处理。

纸面以非对称两栏和轻微层叠表达明信片质感；不需要再印「冬日纪念卡」来说明造型。

### 5.4 卡池与抽卡结果

卡池页面可以突出实际精选人物，这是人物作为主视觉的合适场景。
卡池名称、消耗、保底和抽取方式保持清楚，不添加额外的主题宣言。

单抽使用完整人物展示与侧边票根信息，名称、星级、新获得状态都有明确位置。
十连采用等高票券网格，精选与新获得分别标记；高稀有度通过边框层次、
徽记和小范围暖光提升重量，不以复杂背景牺牲名称可读性。

无图、普通物品和空记录都要有完整布局。一次结果需要包含所有实际抽取项，
不能为了放大六星而丢失其他结果。

### 5.5 邮箱、帮助、商店与小游戏

| 页面 | 布局重点 |
| --- | --- |
| 邮箱列表 | 发件人与标题为阅读起点，时间和领取状态次之；用行距区分信件 |
| 邮件正文 | 一张信纸容纳正文，附件与领取结果位于独立分区 |
| 帮助 | 按分类组织目录与命令示例，长内容可采用分栏；不为每条命令造装饰容器 |
| 商店 | 商品图片、名称、价格、拥有或购买状态；分类通过索引与间距呈现 |
| 游戏身份条 | 紧凑横向身份区，与棋盘保持明确边界，高度遵循现有 64–88px 契约 |
| 棋盘、牌桌与手牌 | 保持游戏元素为主体，仅在周边使用纸面、计分区和细小印记 |
| 游戏结果 | 结果与实际收益先读，过程明细次之；成功或失败用状态标识区别 |
| 赛季信息 | 集中显示实际赛季名称、时间和奖励，主题名在此类有辨识需求的位置可以出现 |

不得通过主题重命名改变命令含义、隐藏答案、领取规则或奖励作用域。

## 6. 固定主题与赛季生命周期

这是一套固定外观。渲染不读取现实月份来改变配色、装饰或版式，也不提供
「初雪／圣诞／岁末」三个日期驱动版本。

赛季时间建议为北京时间 `2026-11-24 00:00` 至 `2027-01-01 00:00`，共 38 天，
结束时间为不包含的上界。本文件仅提出排期，不修改现有赛季配置。

赛季结束后按已有机制结算排名、发放奖励、结束限定卡池并保留赛季记录。
具体发放范围沿用最终赛季配置，不在主题中另写一套规则。

已经获得的主题、立绘与头像框持续保留。用户装备本主题时继续使用这套外观，
直到自行更换；新赛季上线不自动替换玩家装扮。
赛季页面显示对应赛季的实际状态，普通业务页不带失效的赛季倒计时或年份水印。

## 7. 实现边界与素材

遵守 [BaseKit](../../plugins/render/kit.py)、[Tier A 创作指南](tier-a-authoring.md)、
[HOUSE RENDER STYLE](image-responses/00-house-style.md) 和
[utils.cards 分发器](../../utils/cards.py) 的既有接口。

五个基础原子 `background`、`text`、`image`、`panel`、`separator` 共享色板、
字体、间距及纸面规则；三个高曝光表面 `game_identity`、`player_card`、
`pull_reveal` 必须单独设计。业务页面可参照魔女审判使用主题专属布局，
按数据组织阅读顺序，不让所有功能共用一张大卡片模板。

首批素材优先保证界面成立：

- 中文标题与正文字体，以及可选的数字字体；保留许可与来源。
- 平整纸面、低强度雪点、细边与短投影；能由代码生成的简单元素优先代码绘制。
- 签到印记、奖励节点、本人索引、高稀有度票券边框。
- 可选的低矮建筑收边，仅在有空间时使用。

群像立绘、赛季主海报与排名头像框属于后续赛季资产设计，不作为普通页面的
前置条件。印象图不直接裁切成生产 UI 或角色立绘。

装饰与纸面必须确定性渲染；纹理可以缓存，绘制阶段不得修改共享素材。
主题不引入新货币、新签到机制、分阶段奖励或自动换装逻辑。

## 8. 交付与验收

先完成签到、排行榜、资料和抽卡结果四类实际业务预览，确认阅读层级后再推广
到其他页面。以 PNG 实际尺寸及聊天窗口缩小后的效果验收，不以网页小样字号为准。

必须满足：

- 去掉主题名、口号、英文翻译、装饰日期后，页面仍凭布局与材质有明确识别度。
- 第一眼能找到当前页面的业务重点；留白不被额外标签和气氛句填满。
- 签到与排行榜在没有人物插画的情况下完整成立。
- 重要文字满足 22px 可读性底线，无低对比度正文、遮挡或裁切。
- 装备的头像框和称号正常显示，缺失素材不造成布局破洞。
- 长昵称、长任务、密集列表、空数据、长简介及实际日期均能正确换行或降级。
- 抽卡覆盖 1–10 抽、不同稀有度、无图结果，同一行等高且信息完整。
- 窄幅组件、常规页面和宽榜单分别验证，不通过整体缩小来塞入内容。
- 装饰不覆盖正文、棋盘或操作信息，同输入可重复得到相同输出。
- 赛季结束后仍能正常装备和渲染，不出现过期倒计时、自动换肤或固定年份文案。

评审重点是各页面的信息组织、密度与主题一致性，而非人物图或装饰数量。

## 9. 首版实际渲染修订

首版仅还原配色和纵向分组，实际页面缺少小样中的数字对比、印记形状与纸面厚度。
后续实现应以实际业务 PNG 为准，不能只凭「颜色一致、字段齐全」判断完成。

本次落地规则：

- 页头只有一处功能标题，顶部细线负责收边；不增加英文、季号和主题口号。
- 主纸面使用短投影、低强度横向纤维和一处小格纹胶带；头像、普通内层容器不贴胶带。
- 中文使用仓库内圆体；关键展示数字使用已随仓库附带的 Cormorant SC SemiBold。
  该字体只承担数字与短单位，中文继续使用中文字库。签到数字可到 92px，以实际内容测量。
- 签到页将身份与成功印章放在同一行，入账数和连签天数并列，余额从属入账区域。
  进度改为圆形双圈盖章、未完成虚线圈与礼物节点，下面仅标日期序号。
- 任务标题、完成状态、任务名称和奖励按紧凑分区排版，避免所有字段使用相同间隔。
- 榜单同时存在前列和附近记录时，页面采用 1360px 双栏，两栏从同一高度开始，
  保留全部记录；仅有前列时保持常规宽度。本人行采用左侧红索引和轻底色。
- 资料使用一张主要纸面。资产和身份位于左列，已装备立绘位于独立右列；
  取消通用模板在标题下重复显示的赛季名。
- 抽卡结果直接排布票券，不再给整组票券嵌套外层大卡片；票券有撕线与缺口。
  卡池将价格、保底与各档概率分区，避免连续堆叠长文本。
- 人物展示按非透明边界等比适配，去掉源文件透明留边造成的假留白，
  保留所有实际人物像素，不改动原始素材。头像和头像框不使用此处理。

重建入口为 `scripts/preview_winter_ensemble.py`，实际配置与业务画廊写入
`.cache/render-previews/winter-ensemble/index.html`。

## 10. 装饰精度修订
